# 任务计划 Memory 生命周期

[English](task-plan-memory-lifecycle.md) | [简体中文](task-plan-memory-lifecycle_zh_cn.md)

本文档负责共享任务计划的创建、更新、访问和归档生命周期，默认适用于有 Issue 或无 Issue 的 Coding 工作。不负责规划方法、执行授权、父级实时调度状态或权威仓库文档。

## 通用规范

### 默认任务计划

所有现有及未来 Coding 路线都必须在实施前及执行全过程消费本 owner，无需用户额外要求计划或进入专用规划模式。遵守用户明确禁止持久化或更高优先级的写入限制：记录该例外，在获授权上下文内保持有界规划；工具缺失、权限不明或写入失败不得静默当作例外。若用户要求持久化计划而限制阻止持久化，则停止依赖工作并报告冲突。

有 Issue 时，先读取 Issue 和相关讨论，结合当前项目事实分析要求，在实施前综合改动方案。无 Issue 时，对用户明确提出的问题和当前项目事实采用相同流程。初始分析完成前，可用简明的临时计划记录目标、已知事实和待解问题，但不得声称已释放实现方向。实施或依赖派发前，持久化具体计划并确认获准写入操作成功。写入前在获授权上下文审阅计划方案；普通成功写入本身不要求立即全文读回。影响依赖动作的新事实须在该动作前记录；其他实质事实可合并到下一适用计划边界。

### 名称、存储和初始证据

优先复用用户为同一任务指定的 active plan。选择新名称前，确认获准后端使用共享全局存储还是旧版项目本地存储。共享全局存储中，活动与归档规划都必须带同一个已核验仓库 key：`global/token-io-decoupling/repos/<repository-id>/plans/PLAN-[short-english-summary]` 与 `global/token-io-decoupling/repos/<repository-id>/archive-plans/PLAN-[short-english-summary]`。可包含已核实的 Issue 编号；逻辑 Memory 名不含 `.md`。新全局规划不得直接放进共享的 `plans/` 或 `archive-plans/`，也不得用目录 basename、分支、remote URL 或 worktree 路径充当仓库 key。

本存储映射的仓库 key 为 `git-v1-` 加上 `b"token-io-decoupling:git-common-dir:v1\0" + os.fsencode(str(canonical_git_common_dir))` 的十六进制 SHA-256，其中 `\0` 表示一个 NUL 字节。通过可信本地仓库事实解析实际 checkout 根目录和 canonical absolute Git common directory。主工作区和 linked worktrees 共享该目录及 key；独立仓库和独立 clone 使用不同 key，即使名称或 remote 相同。共同目录搬迁会改变 key：应停止并核对旧映射，不得静默丢弃或迁移其规划。缺少或无法确定仓库身份时，阻塞全局路径。这是本机仓库身份，不是跨机器可移植标识。复用旧共同目录路径会复用其 key；在该路径接受新建仓库前，须确认归属并核对已有历史。

明确保留项目本地后端时，使用 `plans/PLAN-[short-english-summary]` 和 `archive-plans/PLAN-[short-english-summary]`；默认物理根为 `<project-root>/.serena/memories/`。该兼容模式不提供跨 worktree 共享。遵从实际配置的 Memory 根和映射，包括获准的数据目录覆盖；不得另建存储或虚构全局根。选定共享全局存储后，身份、根目录、映射或权限不可用时阻塞该路径，不得静默回退项目本地存储。用户自定名称的对应归档映射须在既有授权内明确。已有规划/归档保留原映射，除非另行获准的迁移确认归属、检查碰撞、保留全部字节并核验结果；不得自动收编其他项目未分层的数据或改写已有归档。

确认准确项目/worktree 绑定、存储 scope、全局模式的仓库 key 和有效的记忆维护说明。复用已授权任务已提供或当前上下文已有的计划名称；只有需要发现名称时，才列出所选仓库的规划 topic。仅在需要且当前上下文没有有效内容时读取已存在的匹配计划。全局列表可能暴露其他仓库；可见不构成读取或修改它们的授权。仅复用同一进行中任务的计划；保留无关计划，碰撞时选择不同名称。写入前审阅具体计划，并在依赖工作前确认持久化操作成功。只有为解决信息缺口、上下文过期或失效、写者变化、疑似并发变化、冲突、结果不明或明确内容验证要求时，才刷新存储全文。必需 Memory 能力缺失、必需内容不可访问、持久化失败或必需核验失败时，阻塞依赖工作；报告准确操作并保留最后确认的计划。

### 计划内容

维护一份精简共享计划，包含目标和验收条件、Issue 或用户请求来源、约束和非目标、已核实项目事实与准确来源指针、所选方向和未解问题、有界步骤/依赖/验证方法、已完成/当前/剩余工作，以及实际检查/阻塞/剩余风险。区分事实、假设、提议和已接受决定。使用精简增量和有用的当前证据，不存 transcript、完整 diff、日志或私有推理。精简适用于新增条目，绝不允许用当前状态或最终摘要替换累积内容。保留已有目标、约束、需求变化、带来源的事实、决策理由、阶段进展、共享贡献、失败和验证记录。过时结论须标记为已替代，保留原结论及证据，并补充替代结论、原因和来源；不得静默删除或改写其历史。

### 计划更新的内容保留检查

1. 需要进行内容保留比对或全文替换时，以完整且当前的计划为基线。同一连续、由父级协调的写者轮次中，当前上下文已持有的完整读取可与该写者明确成功的变更合并作为基线。基线缺失、过期、失效，写者交接、疑似并发变化、冲突或结果不明时，刷新完整计划。提纲或未经确认的贡献不能作为基线。
2. 仅合并获准的状态/步骤变更，并追加新事实、结果或证据。目标明确无歧义时优先精确局部编辑；使用 literal 匹配并防止意外多处匹配。全文替换前，取得适用的完整基线并提交合并后的全文，绝不能重新起草摘要。按基线审阅候选内容，确保每条既有记录、贡献、来源、理由及证据仍可追溯；结论变化遵守上述替代规则。
3. 成功的 write/edit 回执确认操作已执行，不证明语义正确、内容保全或并发控制。同一连续受控写者轮次内，已确认变更可加入当前基线，不必每次更新后重新读取全文。仅在用户明确要求、进行实际存储内容验收，或错误、冲突、失效、结果不明要求时，读回存储内容。触发读回后，比对完整相关内容并单独确认新增条目；普通成功写入或抽查不能替代必需的比对。
4. 内容缺失、贡献冲突或写入/读取结果不明时，阻塞受影响汇报、依赖动作和归档。保留最后确认基线，刷新当前状态，并在既有授权内协调后重新检查。不得盲目重放过时的全文替换。比对仅保留于获授权上下文，不持久化 transcript 或私有推理。

### 更新边界与依赖动作

所有参与 Agent，包括父级和验证者，在进入/恢复任务时按需使用同一计划上下文；所需内容缺失或过期时刷新。实质进展及带来源事实在适用的阶段、交接、暂停或完成边界记录。同一阶段的相关更新可合并；普通进度汇报及无关小事实本身不触发写入。影响授权、范围、验收、方向或依赖动作的事实，仍须在受影响动作前记录并分析。成功更新本身不要求立即读回；遵循上述保全及结果不明触发条件。

用户需求变化时，先把新指令及来源记录为待分析。再分析其对范围、依赖、验收和方案的影响；持久化分析和修订计划，确认写入操作成功，并在继续前执行本 owner 触发的必要内容核验。之后父级才可授权受影响改动或派发。子上下文收到变化时，在获准贡献范围内提交并返回父级；子 Agent 不能修订 Contract 或释放工作。只有不依赖待处理变化时，才可继续不受影响的已授权工作。

### 共享访问与更新协调

父级在每次受影响派发中提供准确项目根目录、Memory 名称、相关来源范围和允许贡献。明确每个已分配角色实际需要的读取、贡献提交或写入操作；共享名称不证明跨 Session 可访问。父级作为当前记录写者时，可合并获明确授权的精简贡献。不得要求每个贡献者都具备 Memory 写入工具，也不得将一个 Agent 的成功调用视为其他 Agent 有访问权。必需读取权限缺失时，阻塞依赖该不可访问计划的工作；持久化失败或必需核验失败时，阻塞依赖工作。不得用未经核验的贡献或文件副本替代必需的共享计划证据。

共享计划更新须串行。父级协调同一时刻一个当前记录写者。其他角色可在已释放范围内向父级提交精简且带来源的贡献；这不授予其读写其他记录的权限。同一连续受控写者轮次内，写者可复用其持有的完整基线和自身已确认更新。写者交接或出现并发变化、冲突、失效、结果不明迹象时刷新。不得假定 Memory 工具提供原子比较交换或锁。无法建立当前状态时，暂停受影响汇报/动作；在父级既有授权内协调，不得盲目覆盖或重试过时全文。

计划是共享任务上下文，不是父级实时 mode/count/allocation/epoch 记录、执行 memo 或授权来源；不得存储这些实时调度状态。计划读写不授予其他 Memory、源文件、原始同级上下文或新效果的访问权。遵守 Context Firewall 和各角色已释放范围；提议通过父级返回。验证者只可更新具名计划贡献，对实现和 Git 仍保持只读。执行 memo 标志为 false 不豁免共享任务计划更新。

### 完成与归档

任务未完成或阻塞时保持计划活动。所有适用 Acceptance 条件通过后：

1. 对完整活动计划应用上述内容保留检查：仅更新完成状态/步骤，并追加最终结果、Acceptance 证据和剩余限制。保留累积文档；可追加最终摘要，但绝不能用其替换全文。归档前通过所选生命周期工具的核验回执，或在使用原生 Memory 操作时通过必要的完整内容比对，满足内容保全检查。
2. 保留已验证的最终活动内容作为归档基线，并确认匹配归档目标不存在。仅通过移动命名空间/名称归档本次已完成任务的计划，内容不得变化。碰撞时阻塞移动，保留两个条目并报告。
3. 核实归档内容与最终活动基线完全相同，并确认归档存在且活动名称已不存在。配置的生命周期服务提供匹配的核验归档回执时使用该回执；否则执行必要的归档全文读取和比较。记录缺失、内容差异或更新/归档/必需核验失败均阻塞完成；保留最后确认状态，解决结果不明的效果后才能继续。

已有归档在指令层面不可变：不得编辑、删除、重命名或替换，包括为修复失败的归档比对而修改；工具可见不会技术性强制该规则。此类不一致须报告，交由另行获准的恢复决定处理。不得归档无关或未完成计划。

### 内容保留验收场景

在获准测试范围内使用新建的合成计划，绝不使用用户既有计划。包含多个阶段、目标和约束、带来源的需求变化、有理由的决策、其他贡献者条目、失败检查及后续通过检查。包含“两份未跟踪文件清单已核验”“未发现 PR 模板”等小事实，防止简短最终摘要意外通过。对一项结论注明替代原因和来源，经过上述检查完成计划，再归档。验证每条原记录仍可追溯，旧结论和替代结论并存，最终结果为追加内容，归档等于最终活动基线，且活动名称已消失。另外审查仅含摘要的候选和已占用的归档目标：两者均不得推进至会丢失内容的写入或覆盖归档的移动。分别报告实际演练检查和场景审查；这不证明工具强制不可变，也不恢复过去丢失的内容。

## Codex CLI / ChatGPT Desktop 特别优化指令

### 已配置的确定性生命周期工具

独立 tools MCP 服务提供这些操作，不要求工作流节点或先前工具调用。可选 tools_capabilities 报告后端及存储绑定，workflow_capabilities 不探测计划或 Memory。在本可选 Coding 工作流中，已授权且已配置的 Serena 后端可用时，使用 `task_plan_update`、`task_plan_complete`、`task_plan_archive` 修改计划。仅发现工具不足以继续：须确认后端可用、准确配置 checkout，以及返回的存储 scope/仓库映射。共享全局模式由操作者以实际 Serena `MemoryManager` 显式构建 `SerenaMemoryStore(memory_manager, project_root, storage_scope="global")`；兼容默认值仍为 `storage_scope="project"`。通过显式服务注入或受信任启动 factory 提供该服务。实际全局根须已存在；服务不会初始化或猜测其位置。不得为了让调用通过而虚构 factory、从工具参数加载任意代码、安装依赖或猜测 `.serena` 目录。服务不会自动加载或迁移 Serena 配置。

每个请求仍提供该服务绑定 checkout 的准确绝对 `project_root`，不能选择其他仓库或切换存储 scope。主工作区及 linked worktrees 分别配置的服务派生同一全局仓库身份、history、revision 和 replay scope。检查返回的带项目层级 `memory_name`，不要重建裸名称。全局 history 使用明确仓库身份；旧项目 history 仍绑定 checkout。服务在全局 Memory 效果前重新核对仓库身份，发生改变则失败。capability/receipt 证据不认证调用者，也不授予其他仓库访问权。Git 共同目录语义见 [git-rev-parse](https://git-scm.com/docs/git-rev-parse) 和[仓库布局](https://git-scm.com/docs/gitrepository-layout)。

| 操作 | Agent 输入与必需结果 |
| --- | --- |
| `task_plan_update` | 仅提交具有稳定 ID、文本和来源的类型化记录，以及预期内容版本和操作 ID。创建须明确预期名称不存在。接管已有 Markdown 时，保留其不透明原文并追加类型化记录；显式声明目标和验收标准，不自动推断。替代须引用已有记录并给出原因，旧记录仍保留。绝不提交替换全文、自由格式 patch 或 regex。 |
| `task_plan_complete` | 提供最终结果、限制、预期版本和操作 ID，并将每项当前已声明标准映射到通过的验证记录。先通过追加记录解决 blocker。服务验证结构与内容保留，不能证明输入证据的真实性或语义充分性。 |
| `task_plan_archive` | 提供已完成活动计划身份和预期版本。目标固定为对应归档命名空间。要求内容完全一致的回执及活动名称消失；不得请求引用传播或任意改变目标。 |

准确字段和边界使用当前暴露的 payload schema。服务内部完成全文基线读取、结构化合并、内容保留检查与读回；依赖成功前，检查精简回执中的匹配项目/计划、版本、状态、重放及内容保留结果。回执核实请求操作和内容保留结果后，不得再通过原生 Memory 工具重复全文读回同一内容。版本冲突后，先读取并审阅当前状态，再提出新请求。完全相同的更新/完成重试复用原操作 ID 与 payload；payload 变化须使用新 ID。需要协调或效果不明时阻塞依赖工作；不得用原始 Memory 写入绕过已选服务的失败。这些确定性操作不发起模型或网络请求。

适配器遵守 Serena Memory 访问策略，并操作其实际规范文件。其锁只串行协调参与生命周期工具的调用；原始 Serena 工具和外部写者不会自动参与该锁。不得声称具有针对外部写入的全局比较交换、原始工具 ACL 或归档不可变保证。更强强制边界须由宿主限制其他写入通道。宿主未提供该强制边界不证明其他能力不可用，也不阻止无关获准工作；须准确报告保护范围。

### 原生 Memory 路径

未选择已配置的生命周期服务时，仅使用实际暴露且获准的 Serena 操作，并完成上述全部通用内容保留与存储 scope 检查：`list_memories`、`read_memory`、`write_memory` 或 `edit_memory`，以及获准的归档操作。确认项目激活、选定全局模式的实际根映射、已核验仓库 key 和准确 schema。发现名称时只列出相关计划 topic。普通成功写入/edit 结果确认操作已执行，不要求立即调用全文 `read_memory`；只在上述触发条件下刷新并比较存储内容。`write_memory` 会替换具名 Memory 的全部内容，未取得适用完整基线时不得用它更新；有限变更优先使用获准且精确的 `edit_memory`。全局列表限定为 `global/token-io-decoupling/repos/<repository-id>/plans` 或其对应归档 topic。提供逻辑名称，不得以绝对文件系统路径作为 `memory_name`。当前工具无法确认必需身份或映射时，阻塞共享路径，不得新建 worktree 本地副本替代。原生 `rename_memory` 会传播 `mem:` 引用，因此须先确认效果仍在授权范围内且最终内容比对能够通过，否则停止该归档步骤。绝不把它当成原子禁止覆盖原语。原生 `/plan`、本地回忆和聊天压缩不能持久化此共享记录。一个 Session 的成功调用不证明另一 Agent 的访问权；每个分配 Agent 均须检查。[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp)。

## Claude Code CLI / Claude Desktop 特别优化指令

本仓库的确定性生命周期 MCP 工具不支持该运行环境；将此优化标记为 `Not applicable`，但不得据此推定其原生 MCP 能力不存在。只有连接成功且实际向该 Agent 暴露时，才使用同一个 Serena MCP Memory 服务，并保持上述通用检查和证据，包括已核验仓库身份及带项目层级的全局名称。只通过实际暴露、获授权的本地工具建立 Git 共同目录身份；不得从目录 basename 推断或选择其他仓库可见 topic。按准确项目/名称及当前 schema 发现 `list_memories`/`read_memory`、`write_memory` 或 `edit_memory`，以及获准的归档操作。仅在所需信息缺失或过期时读取；成功写入结果只确认操作执行，不代表内容、语义或并发已核验。全局规划列表限定为已核验仓库 topic；绝对文件系统路径不是 Memory 名。原生 `rename_memory` 会传播 `mem:` 引用：使用前确认效果获准且必需内容保全能够通过，否则阻塞该步骤。发现、审批和可用性可能与 Codex 不同，不假定相同前缀或继承连接。原生 Plan mode、todo 状态及自动记忆不能替代共享计划。必需身份/映射缺失或权限拒绝时阻塞依赖持久化/分配，不得回退新建本地副本。Claude Desktop 绝不通过 GUI 导航建立访问。[Claude Code MCP 工具可用性](https://code.claude.com/docs/en/mcp#tool-availability)。
