# 任务编排 Hooks

Hooks 是主代理按实际任务和状态读取的指令合同。路线定义主要阶段，触发条件决定当前需要执行的检查和动作。

## 合同与明确触发

| Hook | 何时读取 | 当前决策或结果 |
| --- | --- | --- |
| [入口](entry.md) | 收到任务或需要重查用户约束 | 任务范围、验收和代理约束 |
| [规划](planning.md) | 确定任务顺序、分工或调整现有计划 | 任务依赖、责任、交付及验收依据 |
| [主代理执行](execution.md) | 主代理推进自己承担的工作 | 获准范围内的实际产物、进展和证据 |
| [委派](delegation.md) | 准备派发、复用或替换子代理 | 角色、实例、模型和有效强度 |
| [验证](verification.md) | 接收结果、复核交付物或修复 | 当前验收证据和待恢复事项 |
| [恢复](recovery.md) | 中断、失败、结果不明或实例异常 | 真实状态、剩余工作和恢复位置 |
| [交付](delivery.md) | 结束任务或报告阻断 | 最终结果、验证状态和缺项 |

## 宿主能力与触发

主代理根据用户指令、当前产物和宿主回执识别触发条件。编译产物为供代理阅读的合同。委派能力以会话实际暴露的工具为依据。

## 来源整合与链接基准

各合同在执行要求或「规则来源」中链接适用的编排参考。也可从[编排参考目录](../references/README.md)按主题查阅。

## 维护与验收

维护时核对规则链接、编译产物和两条路线的阶段绑定，并结合触发场景检查任务分工、复用和结果回传。
