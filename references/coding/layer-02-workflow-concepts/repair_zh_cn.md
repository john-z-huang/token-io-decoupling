# 修复检查点

[English](repair.md) | [简体中文](repair_zh_cn.md)

## 动作

1. 说明失败证据、受影响路径和能够解决问题的最小修复。
2. 确认修复仍在已批准的 Contract 和决策内。如果修复改变范围、架构、安全、兼容性或其他实质性决策，停止并回到 Contract 和决策检查点。
3. 只执行获授权的修复，并运行针对该修复的聚焦检查。
4. 每次改变状态的修复都必须带着新的最终状态指纹或 epoch 回到验证检查点。

## 通过条件

窄范围修复已完成，新的状态已交给验证，或修复已暂停并明确需要的决策或能力。

## 边界

本检查点不授权大范围清理、无关改进、文档、Git 影响或外部影响。
