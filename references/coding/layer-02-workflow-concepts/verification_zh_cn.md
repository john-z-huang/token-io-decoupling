# 验证检查点

[English](verification.md) | [简体中文](verification_zh_cn.md)

## 动作

1. 记录当前最终状态的指纹或 epoch，以及验收条件。
2. 针对这个准确状态运行适用的最强整体检查和定向检查。
3. 对实质性修改，在 Contract 要求时使用独立的 Change Verification Session。同一 Session 中的检查必须标记为逻辑验证，不能称为独立验证。
4. 记录通过、失败、不可用的检查，假设和剩余风险。
5. 后续任何修改都视为新的最终状态 epoch；较早的结果不能验证新状态。

## 通过条件

每个必需验证项目都有当前证据，或已明确报告未解决项目及其造成的阻塞影响。

## 边界

本检查点报告验证状态，不修复失败，不写文档，不产生 Git 影响，也不能单独宣布整体验收完成。
