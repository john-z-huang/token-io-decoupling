# 任务计划 Memory 生命周期

[English](task-plan-memory-lifecycle.md) | [简体中文](task-plan-memory-lifecycle_zh_cn.md)

本文档负责共享任务计划的创建、更新、访问和归档生命周期，默认适用于有 Issue 或无 Issue 的 Coding 工作。不负责规划方法、执行授权、父级实时调度状态或权威仓库文档。

## 通用规范

### 默认任务计划

所有现有及未来 Coding 路线都必须在实施前及执行全过程消费本 owner，无需用户额外要求计划或进入专用规划模式。遵守用户明确禁止持久化或更高优先级的写入限制：记录该例外，在获授权上下文内保持有界规划；工具缺失、权限不明或写入失败不得静默当作例外。若用户要求持久化计划而限制阻止持久化，则停止依赖工作并报告冲突。

有 Issue 时，先读取 Issue 和相关讨论，结合当前项目事实分析要求，在实施前综合改动方案。无 Issue 时，对用户明确提出的问题和当前项目事实采用相同流程。初始分析完成前，可用简明的临时计划记录目标、已知事实和待解问题，但不得声称已释放实现方向。实施或依赖派发前，必须持久化并读回具体计划。分析期间发现的新事实也必须先记录，再汇报或用于下一项依赖动作。

### 名称、存储和初始证据

优先复用用户为同一任务指定的 active plan；否则使用 `plans/PLAN-[short-english-summary]`，可包含已核实的 Issue 编号。名称不含 `.md`。默认对应归档名为 `archive-plans/PLAN-[short-english-summary]`；用户自定名称的归档映射须在现有任务授权内明确后才可归档。默认项目数据目录下，活动文件为 `<project-root>/.serena/memories/plans/PLAN-[short-english-summary].md`。遵从项目配置的数据目录覆盖及 Memory 工具映射，不硬编码第二套目录或创建文件替代品。

确认准确项目/worktree 绑定和有效的记忆维护说明。创建或更新前列出 Memory，并读取已存在的匹配计划。仅复用同一进行中任务的计划；保留无关计划，碰撞时选择不同名称。写入精简计划，再读回比对意图，之后才继续依赖工作。必需 Memory 能力缺失、必需内容不可访问或写入/读回失败时，阻塞依赖工作；报告准确操作并保留最后确认的计划。

### 计划内容

维护一份精简共享计划，包含目标和验收条件、Issue 或用户请求来源、约束和非目标、已核实项目事实与准确来源指针、所选方向和未解问题、有界步骤/依赖/验证方法、已完成/当前/剩余工作，以及实际检查/阻塞/剩余风险。区分事实、假设、提议和已接受决定。使用精简增量和有用的当前证据，不存 transcript、完整 diff、日志或私有推理。精简适用于新增条目，绝不允许用当前状态或最终摘要替换累积内容。保留已有目标、约束、需求变化、带来源的事实、决策理由、阶段进展、共享贡献、失败和验证记录。过时结论须标记为已替代，保留原结论及证据，并补充替代结论、原因和来源；不得静默删除或改写其历史。

### 每次更新的内容保留检查

1. 写入前立即读取最新活动计划全文；响应分页或截断时须读全每一部分。在获授权上下文中保留该读回内容作为比对基线。读取不完整时阻塞更新；记忆中的提纲或旧快照不足以作为基线。
2. 仅向该基线合并获准的局部状态/步骤变更，并追加新事实、结果或证据。优先局部编辑。若仅支持全文替换，须提交合并后的完整文档，不能重新起草摘要。保留所有其他条目和贡献；结论变化遵守上述替代规则。
3. 读回更新后全文并与基线比较：每条已有记录都必须仍可追溯，来源、理由及证据保持完整；只允许获准状态/步骤更新和显式替代发生差异。另行确认新增条目。写入成功或仅抽查最终状态均不能通过内容保留检查。
4. 内容遗漏、贡献冲突或写入/读回结果不明时，阻塞受影响汇报、依赖动作和归档。保留最后确认基线，重读当前状态，在既有授权内协调后重新检查。不得盲目重放过时的全文替换。比对仅保留于获授权上下文，不持久化 transcript 或私有推理。

### 先更新，再汇报或执行依赖动作

所有参与 Agent，包括父级和验证者，在进入/恢复任务以及依赖内容前读取同一份当前计划。取得新的实质性项目事实或任务进度变化后，先持久化精简事实/状态、来源与下一步，再读回受影响条目，之后才汇报进度、交接或执行依赖该更新的动作。例行且未变化的工具输出无需重复记录。汇报可引用计划，但不能替代更新。

用户需求变化时，先把新指令及来源记录为待分析。再分析其对范围、依赖、验收和方案的影响，持久化并读回分析及修订计划。之后父级才可授权受影响改动或派发。子上下文收到变化时，只在获准贡献范围内记录并返回父级；子 Agent 不能修订 Contract 或释放工作。只有不依赖待处理变化时，才可继续不受影响的已授权工作。

### 共享访问与更新协调

父级在每次受影响派发中提供准确项目根目录、Memory 名称、相关来源范围和允许贡献。核实每个 Agent 能在该项目使用必需 Memory 读取/更新操作；共享名称不证明跨 Session 可访问。必需访问不可用时，停止依赖分配并报告，不得静默用未经核验的代写或文件替代该 Agent 的写入。

共享计划更新须串行。父级协调同一时刻一个写者；每个写者在变更前立即重读最新条目，只修改自己获准的事实/状态，保留其他贡献，并在释放写入轮次前读回变更。不得假定 Memory 工具提供原子比较交换或锁。发生冲突或写入结果不明时，暂停受影响汇报/动作，重读并在父级既有授权内协调，不得盲目覆盖或重试过时全文。

计划是共享任务上下文，不是父级实时 mode/count/allocation/epoch 记录、执行 memo 或授权来源；不得存储这些实时调度状态。计划读写不授予其他 Memory、源文件、原始同级上下文或新效果的访问权。遵守 Context Firewall 和各角色已释放范围；提议通过父级返回。验证者只可更新具名计划贡献，对实现和 Git 仍保持只读。执行 memo 标志为 false 不豁免共享任务计划更新。

### 完成与归档

任务未完成或阻塞时保持计划活动。所有适用 Acceptance 条件通过后：

1. 对活动计划全文应用上述内容保留检查：仅更新完成状态/步骤，并追加最终结果、Acceptance 证据和剩余限制。保留累积文档；可追加最终摘要，但绝不能用其替换全文。归档前读回并通过完整内容保留比对。
2. 保留已验证的最终活动内容作为归档基线，并确认匹配归档目标不存在。仅通过移动命名空间/名称归档本次已完成任务的计划，内容不得变化。碰撞时阻塞移动，保留两个条目并报告。
3. 读回归档全文并与最终活动基线比较：内容必须完全相同。列出 Memory，确认归档存在且活动名称已不存在。记录缺失、内容差异或更新/归档/读回失败均阻塞完成；保留最后确认状态，解决结果不明的效果后才能继续。

已有归档在指令层面不可变：不得编辑、删除、重命名或替换，包括为修复失败的归档比对而修改；工具可见不会技术性强制该规则。此类不一致须报告，交由另行获准的恢复决定处理。不得归档无关或未完成计划。

### 内容保留验收场景

在获准测试范围内使用新建的合成计划，绝不使用用户既有计划。包含多个阶段、目标和约束、带来源的需求变化、有理由的决策、其他贡献者条目、失败检查及后续通过检查。包含“两份未跟踪文件清单已核验”“未发现 PR 模板”等小事实，防止简短最终摘要意外通过。对一项结论注明替代原因和来源，经过上述检查完成计划，再归档。验证每条原记录仍可追溯，旧结论和替代结论并存，最终结果为追加内容，归档等于最终活动基线，且活动名称已消失。另外审查仅含摘要的候选和已占用的归档目标：两者均不得推进至会丢失内容的写入或覆盖归档的移动。分别报告实际演练检查和场景审查；这不证明工具强制不可变，也不恢复过去丢失的内容。

## Codex CLI / ChatGPT Desktop 特别优化指令

### 已配置的确定性生命周期工具

workflow MCP profile 暴露已授权且已配置的 Serena 后端时，使用 `task_plan_update`、`task_plan_complete`、`task_plan_archive` 修改计划。仅发现工具不足以继续：须确认后端可用及准确配置项目。操作者通过显式服务注入或受信任启动 factory 提供实际绑定项目的 Serena `MemoryManager`。不得为了让调用通过而虚构 factory、从工具参数加载任意代码、安装依赖或猜测 `.serena` 目录。服务不会自动加载或迁移 Serena 配置。

| 操作 | Agent 输入与必需结果 |
| --- | --- |
| `task_plan_update` | 仅提交具有稳定 ID、文本和来源的类型化记录，以及预期内容版本和操作 ID。创建须明确预期名称不存在。接管已有 Markdown 时，保留其不透明原文并追加类型化记录；显式声明目标和验收标准，不自动推断。替代须引用已有记录并给出原因，旧记录仍保留。绝不提交替换全文、自由格式 patch 或 regex。 |
| `task_plan_complete` | 提供最终结果、限制、预期版本和操作 ID，并将每项当前已声明标准映射到通过的验证记录。先通过追加记录解决 blocker。服务验证结构与内容保留，不能证明输入证据的真实性或语义充分性。 |
| `task_plan_archive` | 提供已完成活动计划身份和预期版本。目标固定为对应归档命名空间。要求内容完全一致的回执及活动名称消失；不得请求引用传播或任意改变目标。 |

准确字段和边界使用当前暴露的 payload schema。服务内部完成全文基线读取、结构化合并、内容保留检查与读回；依赖成功前，检查精简回执中的匹配项目/计划、版本、状态、重放及内容保留结果。版本冲突后，先读取并审阅当前状态，再提出新请求。完全相同的更新/完成重试复用原操作 ID 与 payload；payload 变化须使用新 ID。需要协调或效果不明时阻塞依赖工作；不得用原始 Memory 写入绕过已选服务的失败。这些确定性操作不发起模型或网络请求。

适配器遵守 Serena Memory 访问策略，并操作其实际规范文件。其锁只串行协调参与生命周期工具的调用；原始 Serena 工具和外部写者不会自动参与该锁。不得声称具有针对外部写入的全局比较交换、原始工具 ACL 或归档不可变保证。更强强制边界须由宿主限制其他写入通道。宿主未提供该强制边界不证明其他能力不可用，也不阻止无关获准工作；须准确报告保护范围。

### 原生 Memory 路径

未选择已配置的生命周期服务时，仅使用实际暴露且获准的 Serena 操作，并完成上述全部通用内容保留检查：`list_memories`、`read_memory`、`write_memory` 或 `edit_memory`，以及获准的归档操作。确认项目激活及准确 schema。原生 `rename_memory` 会传播 `mem:` 引用，因此须先确认效果仍在授权范围内且最终内容比对能够通过，否则停止该归档步骤。绝不把它当成原子禁止覆盖原语。原生 `/plan`、本地回忆和聊天压缩不能持久化此共享记录。一个 Session 的成功调用不证明另一 Agent 的访问权；每个分配 Agent 均须检查。[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp)。

## Claude Code CLI / Claude Desktop 特别优化指令

本仓库的确定性生命周期 MCP 工具不支持该运行环境；将此优化标记为 `Not applicable`，但不得据此推定其原生 MCP 能力不存在。只有连接成功且实际向该 Agent 暴露时，才使用同一个 Serena MCP Memory 服务，并保持上述通用检查和证据。按准确项目/名称及当前 schema 发现 `list_memories`/`read_memory`、`write_memory` 或 `edit_memory`，以及获准的归档操作。原生 `rename_memory` 会传播 `mem:` 引用：使用前确认效果获准且内容保留能够通过，否则阻塞该步骤。发现、审批和可用性可能与 Codex 不同，不假定相同前缀或继承连接。原生 Plan mode、todo 状态及自动记忆不能替代共享计划。缺少必需操作或权限拒绝时阻塞依赖持久化/分配。Claude Desktop 绝不通过 GUI 导航建立访问。[Claude Code MCP 工具可用性](https://code.claude.com/docs/en/mcp#tool-availability)。
