# Coding 子代理消息可见性

[English](delegation-child-message-visibility.md) | [简体中文](delegation-child-message-visibility_zh_cn.md)

本文档负责父级会话中父 Session 与子 Agent 之间文本通信的可见性和证据要求；不授权委派、不定义消息内容范围，也不取代子代理创建、派发、生命周期或上下文传输 owner。

## 通用规范

### 展示完整且可向用户披露的消息正文

父级 Session 与子 Agent 之间的每条上行或下行文本消息，其完整且可向用户披露的正文都必须以普通文本显示在主要父级会话中。发送前展示准确的外发正文；收到后，在依赖、概述或采取后续动作前，展示完整返回正文。外发正文必须与实际载荷一致。若返回正文需要脱敏，必须明确标记每处脱敏，并且后续只能依据展示出的安全内容采取行动。工具调用卡片、活动事件、送达回执、任务状态以及“消息已发送”等通知，除非其中以可读会话文本呈现完整正文，否则均不满足此要求。

单条消息过长时，将其拆分为连续编号的多个部分展示，不得概述、截断或省略任何可向用户披露的内容。不得披露凭证、秘密、私有思维链或其他不可向用户披露的内容；发送前应先对外发载荷脱敏，并展示最终准确的脱敏载荷。对返回内容，应明确标记脱敏处，保留所有可向用户披露的内容，且不得依据隐藏内容采取行动。如果决策所需内容无法安全表达、无法展示完整安全正文，或运行环境只提供状态通知且父级无法复现载荷，则阻塞依赖该消息的切片，并由父级继续持有。

### 保留方向与证据

注明每条消息是外发还是返回；运行环境可提供身份时，还要注明目标子代理或来源子代理。消息正文必须与父级评论清楚区分。转述、摘要或声称内容已发送/收到，均不能作为消息正文的证据。

## Codex CLI / ChatGPT Desktop 特别优化指令

### 使用当前会话暴露的父级控制工具

仅当活动 Session 实际暴露并授权使用时，才调用 `collaboration.spawn_agent`、`collaboration.send_message` 和 `collaboration.followup_task`。只有子代理名额、职责和切片均已放行后才调用 `spawn_agent`，并在实际子任务提示中包含完整任务正文。使用 `send_message` 排队发送已授权消息；需要排队输入并触发子代理新回合时使用 `followup_task`。

每次调用前，先在父级会话以普通文本展示完整安全外发正文，并确保与实际载荷一致。收到子代理回复后，在依赖前先在父级会话展示完整安全正文。调用成功、活动事件、回执、子代理身份或状态都不等于消息正文。若结果未包含正文，将完整正文作为普通文本复现；若无法获取或展示完整安全文本，则阻塞依赖切片。只能使用当前会话直接暴露的消息和结果工具；不得通过桌面 UI 交互找回内容。

## Claude Code CLI / Claude Desktop 特别优化指令

### 使用当前会话暴露的 Agent 提示与返回消息

仅当当前会话实际暴露并授权时，才使用父级控制的 `Agent` 任务提示进行初次派发，或使用按子代理 ID/名称寻址的 `SendMessage` 发送获准 follow-up。调用任一工具前，先在父级会话以普通文本展示完整安全消息正文；收到回复后，在依赖前展示完整安全正文。不得把简短 Agent 标签、任务状态、送达通知或工具回执视为消息正文。未暴露 `SendMessage` 时，将其记录为 `Not applicable`；只有完整正文可显示时才使用普通 Agent 提示/结果路径，否则阻塞依赖切片。
