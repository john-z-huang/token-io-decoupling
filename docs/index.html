Agent orchestration skill

Separate decisions from execution.

Token I/O Decoupling routes an Agent task through explicit responsibilities so semantic decisions, high-volume state handling, and output execution stay clearly separated.

01 / routing

Two flows, one clear entry point.

The skill routes work by the kind of state the task needs to handle: repository state and development artifacts, or visual and temporal state.

coding flow

Repository and development work

Coordinates coding tasks from project exploration through implementation and independent verification.

  • Explore source and project state progressively
  • Materialize code and configuration changes
  • Run focused implementation checks
  • Route final verification and Git delivery separately
multimodal flow

Visual and temporal state work

Coordinates tasks that consume GUI, browser, image, screenshot, video, or other visual state.

  • Observe visual state progressively
  • Keep visual context owned by its flow
  • Hand off only stable decisions to Coding when needed
  • Verify the resulting visual behavior when required

02 / capabilities

Functions that keep work aligned.

Each function defines what information moves forward and which responsibility owns the next action.

Task routing

Choose Coding or Multimodal based on the task’s primary state and execution needs.

Role separation

Give decisions, output materialization, verification, and Git operations distinct responsibilities.

Semantic Contract

Carry the goal, constraints, decisions, and acceptance criteria as a stable task anchor.

Context Firewall

Keep raw project state with the responsibility that owns it and pass only necessary context onward.

Independent verification

Assess the final changed state against the acceptance criteria without inheriting implementation history.

Evidence on demand

Request targeted facts or references when a decision needs more evidence instead of replaying full state.

03 / execution

A task moves through explicit steps.

The workflow keeps each transition bounded by a goal, an owner, and an acceptance condition.

STEP 01

Route the task

Select the flow that owns the task’s primary state: Coding or Multimodal.

STEP 02

Define the contract

Stabilize the goal, constraints, decisions, and acceptance criteria before execution.

STEP 03

Materialize the output

Let the responsible output role explore state, implement the approved direction, and return focused feedback.

STEP 04

Check the final state

Use independent verification to map the final result back to the acceptance criteria.
