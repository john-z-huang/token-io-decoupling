01 / 路由

两条 Flow，一个清晰入口。

Skill 根据任务需要处理的主要状态进行路由：仓库与开发产物，或视觉与时间状态。

coding flow

仓库与开发工作

协调从项目探索到实现和独立验证的 Coding 任务。

  • 渐进式探索源代码与项目状态
  • 物化代码和配置改动
  • 运行聚焦的实现检查
  • 将最终验证和 Git 交付分开路由
multimodal flow

视觉与时间状态工作

协调需要消费 GUI、浏览器、图片、截图、视频或其他视觉状态的任务。

  • 渐进式观察视觉状态
  • 让视觉上下文由对应 Flow 持有
  • 需要进入 Coding 时只移交稳定决策
  • 在必要时验证最终视觉行为

02 / 功能

让工作保持一致的功能。

每项功能都定义信息如何继续传递，以及下一步行动由谁负责。

任务路由

根据任务的主要状态和执行需求选择 Coding 或 Multimodal。

角色分工

让决策、输出物化、验证以及 Git 操作各自拥有明确职责。

Semantic Contract

把目标、约束、决策和验收标准作为稳定的任务锚点进行传递。

Context Firewall

让原始项目状态留在对应职责中，只向后续职责传递必要上下文。

独立验证

在不继承实现历史的情况下，依据验收标准检查最终变更状态。

按需获取证据

当决策需要更多依据时获取定向事实或引用，避免重复传递完整状态。

03 / 执行

任务经过明确的执行步骤。

每次转换都由目标、负责人和验收条件限定边界。

STEP 01

路由任务

根据任务的主要状态选择 Coding 或 Multimodal。

STEP 02

定义 Contract

在执行前稳定目标、约束、决策和验收标准。

STEP 03

物化输出

由负责输出的角色探索状态、实现已批准方向并返回聚焦反馈。

STEP 04

检查最终状态

使用独立验证将最终结果映射回验收标准。
